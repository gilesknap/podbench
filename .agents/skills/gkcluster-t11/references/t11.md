# T11 on gkcluster

Revalidate these expected values because the cluster and Git branches can move:

- namespace: `t11-beamline`
- root Argo Application: `t11` in `argo-cd`
- root source: `gilesknap/t11-deployment`, branch `main`, path `apps`
- service source: `gilesknap/t11-services`, branch `main`
- cluster source: `gilesknap/tpi-k3s-ansible`, branch `main`
- cluster root Application: `all-cluster-services`
- admin kubeconfig: `/workspaces/config`, with no default namespace

The deployment and service repositories are forks used to assemble a realistic
test beamline. Keep machine-specific adaptations in cluster IaC where possible.

## Baseline

Use explicit namespace and kubeconfig flags. Capture enough state to explain
scheduling rather than relying only on Pod phase:

```sh
kubectl --kubeconfig /workspaces/config get nodes \
  -L kubernetes.io/arch -o wide
kubectl --kubeconfig /workspaces/config get applications -n argo-cd
kubectl --kubeconfig /workspaces/config get pods,pvc -n t11-beamline -o wide
kubectl --kubeconfig /workspaces/config get storageclass
```

Inspect node taints separately. The cluster normally has ARM64 nodes, untainted
AMD64 node `nuc2`, and AMD64 workstation `ws03` tainted
`workstation=true:NoSchedule`; verify this live.

## Scheduling policy

The `force-amd64-scheduling` NamespacedMutatingPolicy is owned by the `kyverno`
Application. Its intended behavior is:

- pin a Pod to `kubernetes.io/arch: amd64` if any regular or init container uses
  `ghcr.io/epics-containers/ioc-*`;
- also pin BlueAPI, Numtracker, and EPICS Gateways image repositories regardless
  of tag or digest;
- do not add the workstation toleration;
- leave other, multi-architecture Pods unpinned.

Validate both branches with server-side dry-run Pods before restarting workloads.
Inspect registry indexes when the image set changes; do not infer architecture
support from a running node or image name.

To apply a changed admission policy to existing workloads, delete the exact
controller-owned Pods after listing and reviewing them. Do not delete Deployments
or StatefulSets, and leave completed Job Pods alone. After recreation verify each
Pod's images, node selector, workstation toleration, assigned node, phase, and
readiness. Unschedulable Pods may have PVC node affinity conflicting with image
architecture; deleting their controller will not fix that.

## Storage and identities

`nfs-rwx` is the expected default StorageClass, backed by the QNAP export
`192.168.1.3:/k8s-dynamic`. It is for dynamically provisioned RWX claims and uses
Retain semantics. Existing `local-path` RWO claims remain node-affined and must be
treated as data-bearing even when their Pods are Pending.

IOC workloads currently use UID:GID `36261:36261`; BlueAPI uses UID `1000`.
Provisioned NFS directories may arrive as `root:root` mode `0755`, which prevents
those identities from writing. Diagnose using numeric ownership from a temporary
Pod mounting the export root. Prefer narrow ownership or group fixes over `0777`.
Never recursively change ownership, delete a claim, or recreate a PV until the
exact subdirectory, consuming Pods, required identities, and data value have been
confirmed. Remove temporary probe Pods when finished.

## Gateway access and diagnosis

The EPICS gateway expects ServiceAccount `default-full-access-mounted`. On this
cluster it should have an automounted token and namespace-scoped `get`, `list`,
and `watch` on Pods and Services, not administrative access. Verify permissions
with `kubectl auth can-i --as=system:serviceaccount:t11-beamline:...`.

## Synoptic initialization

The Synoptic init container must work under the IOC UID/GID; never install Git
with `apt-get` at runtime. A pinned `ubuntu-devcontainer` image supplies both Git
and uv. Mount an `emptyDir` at `HOME=/tmp` for uv's cache, managed Python, tool
environment, and Git configuration. It survives init-container retries but not
Pod replacement, which is sufficient for disposable downloaded artifacts.

For `techui-builder` 0.7.8, `synoptic/techui.yaml` requires `beamline.domain`,
`beamline.location`, `beamline.desc`, and `beamline.url`. The older `short_dom`
and `long_dom` fields are invalid; the long-form beamline identifier belongs in
`location`. Validate with the same `generate-jsonmap` and `status` commands used
by the init container, not merely YAML parsing.

Shared Synoptic source affects both the `t11-epics-opis` and `bl11t-synoptic`
Argo applications. Hard-refresh both, wait for the expected Git revision, and
then require the init container to terminate successfully and the main container
to become Ready.

For failures, inspect in this order:

1. Argo Application conditions and missing/out-of-sync resources.
2. Pod scheduling events, selectors, tolerations, taints, and PV node affinity.
3. Init-container status and logs before application-container logs.
4. Numeric security contexts and mounted-directory ownership.
5. ServiceAccount existence and exact authorization.
6. Readiness, service endpoints, and application logs after startup.

Report which layer failed and retain successful evidence. Architecture success,
volume mounting, and application startup are separate acceptance boundaries.
