# Phase 1 — does `helm.sh/resource-policy: keep` survive prune-on-sync?

2026-08-22, `p47-beamline` on pollux, through
`k8s/p47-beamline-claude-hgv27681-tunnel.kubeconfig`.

**Answer: no.** A resource carrying `helm.sh/resource-policy: keep` and nothing
else is pruned on an ordinary Argo sync the moment it leaves the desired state.
`Prune=false` is load-bearing and issue #190 is a real gap, not a redundant belt.

This is the measurement the last run could not supply: its prototype carried
`Prune=false,Delete=false` as well as `keep`, so the survival it recorded was
not attributable to either.

---

## What was deployed, and where

Not on either live IOC, and not on any claim anything depends on.
`p47-epics-opis` was chosen as the host because it is the one service in
`p47-services` with **its own `Chart.yaml`, an empty `values.yaml` and no
`.helm-shared` symlink** — so the probe template was invisible to every IOC in
the repo.

`p47-services` branch `podbench-prune-probe` (`9f9c1e5`), one file,
`services/p47-epics-opis/templates/podbench-prune-probe.yaml`, rendering three
resources that nothing mounts or consumes:

| resource | annotations |
|---|---|
| `podbench-prune-probe-control` (ConfigMap) | **none** |
| `podbench-prune-probe-keep-cm` (ConfigMap) | `helm.sh/resource-policy: keep` |
| `podbench-prune-probe-keep-pvc` (PVC, 1Gi, `netapp`) | `helm.sh/resource-policy: keep` |

The control is what makes the other two readable: a survival with nothing to
compare it against proves only that the sync never happened.

The PVC matters separately from the ConfigMap because a PVC is the kind podbench
actually ships, and it carries a `kubernetes.io/pvc-protection` finalizer. The
`netapp` class is `volumeBindingMode: Immediate`, so it **Bound** rather than
sitting Pending — the same state a real hotfix claim is in.

## The two events

`p47-deployment` `apps/values.yaml`, `p47-epics-opis.targetRevision`:

* `8996ff3` — `main` → `podbench-prune-probe`. Pushed 18:47Z.
* `808abd7` — reverted. Pushed 18:55:57Z.

The revert is the event under test, and it is deliberately the same one Phase 5
ends on: nobody deletes the Argo Application to end a hotfix, they take the
layout back out. Child Applications generated by `argocd-apps` 5.5.0 carry
`syncPolicy.automated: {prune: true, selfHeal: true}`
(`ec-helm-charts` `Charts/argocd-apps/templates/_apps.tpl:59-62`), so this is
prune-on-sync with nothing manual in the path.

## Pruned — 18:59:08Z, all three

Three minutes and eleven seconds after the revert was pushed:

```
$ kubectl -n p47-beamline get cm,pvc | grep prune-probe
(nothing)

$ kubectl -n p47-beamline get cm/podbench-prune-probe-keep-cm
Error from server (NotFound): configmaps "podbench-prune-probe-keep-cm" not found

$ kubectl -n p47-beamline get pvc/podbench-prune-probe-keep-pvc
Error from server (NotFound): persistentvolumeclaims "podbench-prune-probe-keep-pvc" not found
```

**And the PV went with it.** `netapp` is `reclaimPolicy: Delete`, so the storage
was destroyed, not released:

```
$ kubectl get pv pvc-d103160d-20c8-4077-8977-1f53ead22e8e
Error from server (NotFound): persistentvolumes "pvc-d103160d-20c8-4077-8977-1f53ead22e8e" not found
```

That is the whole failure mode in one line: on this cluster a keep-only hotfix
claim is not merely unbound, it is **gone**, and the running code silently
reverts to the released image.

## What this settles, and what it does not

**Settles.** `helm.sh/resource-policy: keep` alone does not survive
prune-on-sync — consistent with Argo's own documentation, which maps it to
`Delete=false` and says nothing about `Prune`. The chart carries both
annotations from here, and Helm's is not redundant: it is what a plain
`helm uninstall` honours for anyone not running Argo at all.

**Does not settle.** That `Prune=false` *would* have saved it was not
re-measured here — the 2026-08-22 prototype already showed both-annotations
surviving this identical event
(`.claude/evidence/phase5-live-run-on-p47.md`), and pairing that with this run
is what attributes the survival. Phase 5 re-proves the pair end to end.

Kind-independence was worth one extra resource and got it: the ConfigMap and the
Bound PVC behaved identically, so nothing here turns on PVC-specific handling.

## State afterwards

Clean. All three probe resources are gone, the PV with them, and **no podbench
claim of any kind remains on `p47-beamline`** — the two 2Gi claims the last run
left behind had already been deleted before this run started. `p47-deployment`
is back on `main` for every service. The `p47-services` branch
`podbench-prune-probe` was deleted once this file was written.

Nothing needed a human, and nothing was left for one.
